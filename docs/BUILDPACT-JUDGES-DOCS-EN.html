01 / Technical README

Start here: what is live, how to test it

BuildPact is a Kickstarter-like funding flow plus an on-chain cap table. A creator publishes an idea and shares; members sign their acceptance; finalization locks the deal; backers fund a PDA vault; one instruction distributes the fee and member payouts.

02 / Architecture

One pact, two planes of trust

The settlement-critical rules live on Solana. Supabase handles the social/product layer — authentication and realtime collaboration — but it does not decide shares, approvals, escrow balances or payouts.

Deployed config reference

The project documentation identifies a Config PDA derived from ["config"], with protocol_fee_bps = 200 (2%).

Config PDA seeds:

Protocol fee:
200 bps = 2%

V1 enforcement is intentionally immutable in the current program: fee and protocol wallet are constants. The historical Config account remains a reference for the deployed Devnet state.

Canonical address derivation

  ["project", creator, project_id],
  program_id
)
Vault = PDA(

)

No client-supplied vault address is trusted: Anchor re-derives both PDAs from the stored project data.

03 / Security audit summary

What was found — and what changed

The audit summary below is grounded in the supplied Anchor source and project notes. It is an engineering review summary, not a claim of a formal third-party audit or mainnet readiness.

FIXED · CRITICAL V1 FINDING

Protocol fee wallet could be redirected

create_project previously accepted an arbitrary protocol_wallet. A direct caller could have redirected the 2% fee.

Fix: hardcoded PROTOCOL_WALLET plus require!(protocol_wallet == PROTOCOL_WALLET, InvalidProtocolWallet). Distribution also applies an Anchor address constraint.

FIXED · FUNDS SAFETY

Vault dust could block closure

Finalized projects can now close when the vault contains only rent plus at most 1,000 lamports of dust. This prevents rounding residue from locking the account forever.

FIXED · OPEN VAULT CLOSURE

Direct SOL dust on an open vault

The vault balance threshold is now checked for every project status, not only finalized projects. A creator cannot sweep meaningful funds from an open project's vault via close_project.

FIXED · ACCOUNTABILITY

Distribution event accuracy

FundsDistributed emits the exact sum transferred to members, rather than the pre-rounding amount. Events exist for create, member changes, approvals, finalize, funding, distribution and close.

POST-HACKATHON

Upgrade authority rotation

Move upgrade authority to a dedicated, controlled key before mainnet. This is explicitly not presented as complete.

OPERATIONAL

Mobile wallet reliability

Desktop demo is recommended. Backpack on Seeker Devnet was reported as reliable; Phantom/Solflare mobile flows had signing-loop issues.

Mainnet gate: repeat the full negative-test suite on the target cluster, verify the deployed IDL and Program ID, review upgrade authority, and perform an independent audit.
04 / User flow · demo script

Six transactions, one clear story

Use a founder wallet and a second Devnet wallet. Keep Solscan Devnet open in a second tab to make the “no mock data” claim observable.

01 · CREATEFounder publishes title, pitch, role and initial share.
02 · JOINCreator adds a member wallet, role and share.
03 · APPROVEEach member signs their own acceptance.
04 · FINALIZECreator locks the pact at exactly 10,000 bps.
05 · FUNDBacker sends SOL to the Vault PDA escrow.
06 · DISTRIBUTE2% fee, then 98% pro-rata to members.

Marketplace proof
“These are not mockups — every pact here is a real on-chain account. Let me prove it.” Open the project history and show a finalized Devnet transaction.
Approval guarantee
“Every member has to approve on-chain before the founder can lock the deal — nobody gets added without their own signature.”
Finality & payouts
“Shares total 100%, everyone approved — now I lock it. Funds go into a PDA escrow, then distribute automatically: 2% protocol fee, 98% split by share.”

Before you click

05 / Complete specification

Instructions, accounts, seeds and checks

The following is a compact reading guide to the current Anchor program. Length limits are byte limits in Rust String::len().

Instruction matrix

InstructionPurposeRequired checks
create_projectInitialize Project with creator as first approved member.Project PDA; id ≤ 20 bytes; title ≤ 40; description ≤ 280; role ≤ 24; share ≤ 10,000; locked fee wallet.
add_memberAdd pending member.Creator signer; project Open; max 8; no duplicate; cumulative shares ≤ 10,000; checked arithmetic.
remove_memberRemove a pending non-creator member.Creator signer; Open; member exists; not approved.
approveMember accepts their role/share.Member signer; wallet is in project; not already approved; project Open.
finalizeLock project into Finalized state.Creator signer; ≥2 members; all approved; total exactly 10,000 bps.
fundTransfer SOL to Vault PDA.Project/Vault PDAs; project Finalized; amount > 0.
distributePay fee and members from Vault.Finalized; exact recipient list/order; available balance; checked math; vault signer seeds.
close_projectClose project and return rent to creator.Creator signer; project/Vault PDAs; vault ≤ rent + dust tolerance.

Data model

Project {
  creator: Pubkey,
  project_id: String,
  title: String,
  description: String,
  members: Vec<Member>,
  status: Open | Finalized,
  protocol_wallet: Pubkey,
  bump: u8,
}

Member {
  wallet: Pubkey,
  role: String,
  share_bps: u16,
  approved: bool,
}

Distribution formula

available = vault_balance - rent_minimum
fee = available × 200 / 10,000
after_fee = available - fee
member_payout = after_fee × share_bps / 10,000

// all arithmetic uses checked operations
// integer division may leave dust

06 / Roadmap V2

From guaranteed shares to programmable collaboration

V1 deliberately solves one hard problem first: make the agreement and payout split verifiable. V2 expands the protocol only after Devnet validation, review and mainnet readiness work.

Gate 0
Now · Devnet

Stabilize the proof

Complete the judge flow, maintain the real on-chain marketplace, monitor distribution events, and document failure modes. Keep mainnet out of scope until the security gate is met.

Gate 1
Post-hackathon

Mainnet readiness

Independent audit; rotate upgrade authority to a dedicated key; verify deployment and IDL; add operational monitoring, incident response and a carefully scoped mainnet launch.

V2 · Product

Milestone payments

Split a pact into deliverables and release funds only after explicit milestone approvals. Preserve the finalized share guarantee while adding execution accountability.

V2 · Network

On-chain builder reputation

Portable contribution history, verified completions and dispute-aware reputation signals — designed to reward delivery without turning the protocol into an opaque score.

V2 · Resilience

Member replacement & lifecycle

Support a safe replacement path through a new pact or controlled amendment model, with clear consent boundaries and no silent rewrite of finalized economics.

V2 · Scale

Indexing and richer settlement

Move marketplace discovery from client-side account scans to an indexer/event pipeline; evaluate stablecoin funding, batched payouts and storage options as usage grows.

Scalability principles

  • Use emitted Anchor events for indexing instead of polling every account.
  • Paginate and filter discovery server-side at scale.
  • Batch or stream distributions only after preserving recipient-order and accounting invariants.
  • Keep collaboration metadata off-chain while anchoring settlement facts on-chain.

What V2 does not claim today

Mainnet security, production-scale throughput, tokenomics, market adoption, and quantified TAM/SAM/SOM are not established by this Devnet build. They are validation work, not marketing facts.
