2. Actual technical architecture

  • Front end: Vite + React 19 + TypeScript + Tailwind. Entry point src/main.tsx, hash-based routing (src/lib/router.ts), one route per page.
  • Wallet: @solana/wallet-adapter with three adapters — SolanaMobileWalletAdapter (Seed Vault / Seeker), Phantom, Solflare. The appIdentity.uri is derived from window.location.origin: an identity pinned to a stale Vercel URL would break MWA authorization (fixed).
  • On-chain: Anchor program with create_project, add_member, remove_member, approve, finalize, fund, distribute, close_project, update_description. No mutable admin account: fees and the protocol wallet are compiled constants.
  • Off-chain: Supabase (profiles, media, discussion, document vault, builder directory, translations) + Edge Functions (push, contact, network-write, quest-write, update-profile, translate, vault, project-write, chat-moderate, open-roles). Standing rule: no unverified public write — sensitive writes go through a wallet signature.

The how of these changes — work-item numbering, commits, internal mechanisms — lives in PLAN-CHANTIERS-PREMIUM-2026-10-08.md. This document says what changed, not how: a commit hash or a CSS class name means nothing to a reader who is not inside the repo.

The premium profile now writes to the server. This is the day's most important fix, and it does not look like a bug: the premium form asked for a wallet signature… then wrote to the browser only. A pseudo or avatar changed on the premium side therefore showed up neither in the builder directory nor on another device — only the legacy portal really wrote. The signature it asked for was pointless afterwards: it carried a message the server never verified. Saving now writes locally first (the card updates immediately and stays readable offline), then sends the full profile to the update-profile Edge Function with the canonical message it can verify. The remote profile is read back before sending, so a field the premium form does not expose (bio, links, availability, theme palette) is not erased in the process.

Two fixes outside those changes, on 2026-10-08. The background-style picker offered three "HD" variants whose images were never committed: three console 404s on every settings open, and empty thumbnails. The three options are removed; an already-stored value falls back cleanly to the default, and a test now rejects any reference to a file missing from public/. Separately, a square banner overflowed its thumbnail and hid the title, description and figures, while the fallback gradient was hard-coded in three places, hence theme-blind: both are fixed, with a test that sweeps every premium page.

5. Verify the app yourself

From buildpact-75mv/:

npm run typecheck     # tsc, must exit 0
npm test              # node --test suite, 66/66 on 2026-10-08
npm run build         # typecheck + vite build
npm run guard:push    # rejects a batch larger than 5 files
npm run guard:install # run ONCE per clone: installs the pre-push hook

Working rules:

  • At most 5 files per push (enforced by the committed guard); explicit escape hatch: ALLOW_MASS_PUSH=1.
  • Two consecutive failures on the same problem → STOP and ask.
  • A project card is edited in PremiumProjectCard, never in the pages.

6. Known limitations, not glossed over

LimitationVerified detail
Signing flows not tested by an agentCreating a pact, funding, distributing: all require a real wallet. None of these flows has been run by an agent; they were validated by hand by Noah.
Real push subscription never exercised locallyThe infrastructure exists (public/push-sw.js, supabase/functions/push, migration create_push_subscriptions). Only the VAPID keypair is missing. A real subscription is impossible from an automation browser: Notification.permission is denied there, and no agent tool can grant it.
Two demo pacts have a polluted descriptionThe on-chain description field literally starts with [🤝 Les deux]. This is not a display defect: it is the stored text. It can be fixed through updateDescription (EditDescriptionModal), i.e. with a signature.
Profile saving not exercised with a real walletThe premium profile's remote write is covered by unit tests and by the Edge Function contract (identical to the legacy portal, already in service), but the full path — signing with a real wallet, then reading the profile back from the directory — has not been run by an agent: it requires a wallet.
/v1 is still reachableTwo live skins in parallel until it is removed.

Why two reference documents (FR and EN) instead of one

Because the hackathon English text was an automatic line-by-line merge (French then English glued together), sometimes wrong ("damage" for "casse"). Today's EN versions are written, not generated.The .html files are produced from the .md files by docs/outils/md-to-html.mjs: one source per language, so Markdown and HTML cannot diverge.

Check that the documents have not diverged

From the app root (buildpact-75mv/):

node docs/outils/verifier-docs.mjs   # fails if a .html no longer matches its .md

The check regenerates each page in memory and compares it byte for byte with the one on disk: it catches a .md edited without regenerating, as well as a .html edited by hand. Only pages carrying the generator's signature are compared — the August roadmaps exist as .md and .html without either deriving from the other, and including them would raise two false alarms.
